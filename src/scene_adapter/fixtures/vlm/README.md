# SceneDescription v1: обязательные offline-входы ПР10

JSON Schema: `contracts/scene-description-v1.schema.json`; ROS-интерфейс:
`interfaces/msg/SceneDescription.msg` относительно корня распакованного kit.
Fixtures — авторские контрактные данные курса, не ответы живой модели.

| Вход | now_s в тесте | Ожидаемый результат |
|---|---:|---|
| scene-clear.json | 0.1 | valid |
| scene-low-confidence.json | 0.1 | unknown / low_confidence |
| scene-stale.json | 2.0 | unknown / stale_input |
| scene-extra-command.json | 0.1 | unknown / invalid_schema |

Порог уверенности 0.5, максимальный возраст 0.25 с. Часы источника и проверки
должны принадлежать одной шкале времени. В JSON stamp_s=0 или 1; это секунды
контролируемого теста. Не заменяйте их текущим временем при чтении mock/кэша.
В unit-тестах передайте now_s явно. В ROS-тесте включите use_sim_time и
подайте соответствующий `/clock`; убедитесь, что метка получена до проверки.
Замороженный `/clock` останавливает ROS-таймеры: для такого smoke-теста
можно публиковать из обработчика сообщения или использовать wall/steady tick,
но возраст вычисляйте по ROS-часам.

Поле drive запрещено целиком. У неизвестного результата сохраняйте допустимые
метку и frame исходного наблюдения, категории unknown, расстояния null,
confidence=0 и причину отказа. Не выводите метры из диагностического PNG/VLM-опыта.

JSON Schema-библиотеку укажите в зависимостях своего пакета. В выбранном
Lyrical-образе python3-jsonschema устанавливается отдельно до offline-тестов.
Все обязательные прогоны выполняются без API, токена и загрузки весов.
