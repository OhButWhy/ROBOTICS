# PR09 — анализ ошибок baseline

## 1. Утечка capture_id между calibration и test

- Sample ID: sample-03, sample-04.
- Причина: исходный manifest помещал sample-03 и sample-04 в test,
  хотя их capture_id — capture-a и capture-b. Эти группы по контракту
  целиком относятся к calibration.
- Влияние: исходный test содержал лёгкие кадры с двумя правильными
  детекциями (TP=2, FP=0, FN=0, F1=1.0). Такая оценка недопустима,
  поскольку нарушена независимость групп.
- Исправление: sample-01...sample-04 находятся в calibration,
  sample-05 и sample-06 — в test.
- Повторная проверка: запуск evaluate_perception.py без --allow-leak.
  Результат: split_valid=true, split_issues=[].

## 2. Пропуск тёмного объекта

- Sample ID: sample-05.
- Причина: baseline ищет красные связные области по фиксированным
  порогам red_min=180, green_max=120, blue_max=120. Тёмный объект
  не удовлетворяет этим условиям.
- Влияние: объект из annotation не обнаружен, FN=1.
- Повторная проверка: повторный запуск evaluator на неизменённом
  fixture и проверка predictions для sample-05. Ожидается пустой
  список objects и один false negative.
- Ограничение: пороги baseline не подбираются по test.

## 3. Ложная красная связная область

- Sample ID: sample-06.
- Причина: красная область фона удовлетворяет цветовому критерию
  baseline, но не является размеченным объектом.
- Влияние: лишняя детекция bbox [0, 0, 1, 2], FP=1.
  Правильная детекция bbox [4, 3, 2, 2] является TP=1.
- Повторная проверка: повторный запуск evaluator и сравнение
  predictions с annotations/sample-06.json.
- Важно: наличие геометрически корректной 3D-проекции для ложной
  2D-детекции не превращает её в реальный объект.

## Итог после исправления split

- test_samples: sample-05, sample-06.
- TP: 1.
- FP: 1.
- FN: 1.
- Precision: 0.5.
- Recall: 0.5.
- F1: 0.5.
- mean_iou: 1.0 только для сопоставленного TP.
- split_valid: true.

Метрики относятся к 2D-детекциям. Они не являются оценкой точности 3D-координат или глубины.
